## 已复现并修复的问题

首轮完整运行是 **1964 passed、5 failed、2 warnings**，不是交付验收。随后修复及独立复核覆盖：

1. HTTP 与人工动作审阅枚举不一致：全链仅用 `approved` / `rejected`，拒绝旧别名；说明须非空。
2. 求解期间来源 revision 更新后遗留待执行动作：返回边界拒绝旧计算并清除 pending action。
3. 仅传 `callbacks: []` 仍继承环境 RunnableConfig 回调：受控图作用域设置并恢复回调 contextvar，同时禁用 tracing。
4. 普通内容 hash 可被重新计算，不能证明可信签发：计算到签发使用进程内 origin seal，签发单独持久化 Store receipt，送审核验七份记录。
5. 推进中断后旧 partial 回执可能结清更新意图：引入持久化整厂意图和最低回执序号，不把未知当拒绝。
6. **丢失 ACK 后取消崩溃**：receiver 已有 partial sequence 1，publisher 仍为 0；取消在 receiver 前崩溃后，旧 partial 1 曾可能错误结清取消并允许执行。新增取消语义栅栏：只有权威 cancelled 或已开始的真实执行状态才可结清，partial/accepted 且 execution none 即使序号足够也不算取消结果。

取消修复增加四个回归案例，独立复验另通过 **14 个范围测试和 6 个合成探针**，覆盖丢失递送/推进 ACK、整厂意图、真实取消、running/completed/failed 回读。最终全量包含相关测试。

中间全量结果依次为 **2090 / 2094 / 2099 passed**（均 2 warnings），分别属于不同修订；最终只引用上表的 **2124**，不叠加计数。

## 独立求解与真实性边界

微型 oracle 限于最多 4 道剩余工序、horizon 不超过 12 分钟，独立枚举机器和整数开始时间，可行性判断不调用 solver 或 validator。25 个原创案例与真实 CP-SAT 对比，不能推广为一般规模最优性证明。

独验从快照重算覆盖、BOM、库存、WIP、资格、日历、资源、冻结、路线、真实相邻换型与目标。事件模拟另外创建库存、资源、机器和工序状态，以队列推进事件，不复制独验 trace 或候选目标充作执行结果；中途阻断返回 partial execution，不伪造 completed。

HMAC、origin seal 和签发 receipt 解决各自受信边界中的错误或替换，不抵御能任意修改代码、全部数据库与秘密的恶意管理员，不提供物理执行或秘密持有方之间的不可否认性。默认人工审阅不自动强制不同自然人双人复核。
